# Beginner-First Content Style Guide v1

## Purpose
Outline tone, structure, and accessibility expectations for the Codex rewrite of Tanium TCO modules.

## Core Principles
- Speak directly to beginners using plain language.
- Use the Why → What → How → Apply progression in every module.
- Provide context first, then terminology, then guided action, then practical application.
- Reinforce key ideas with analogies, visuals, and active practice.

## Structural Pattern
1. **Why** – Establish relevance with relatable analogy and real-world stakes.
2. **What** – Define concepts in plain language, surface vocabulary support, and map to exam domains.
3. **How** – Provide step-by-step walkthroughs, mini-practice tasks, and debugging guidance.
4. **Apply** – Present realistic scenarios, assessment checkpoints, and reflection prompts.

Every section ends with:
- **Active Recall**: 2–5 short questions.
- **Mini-Practice**: 1–3 tasks that can be completed quickly.
- **One-Sentence Summary** capturing the key takeaway.

## Tone & Voice
- Conversational, encouraging, and respectful.
- Prefer short sentences and contractions where appropriate.
- Introduce jargon only after giving a simple explanation; link or define inline.

## Visual & Analogy Standards
- Include at least one accessible analogy per module to anchor learning.
- Provide diagram placeholders with captions; export final diagrams at 1440px width minimum.
- Follow screenshot standards: annotate focus areas, ensure 4.5:1 contrast, add descriptive alt text.

## Accessibility Requirements (WCAG AA)
- Maintain proper heading hierarchy (no skipped levels).
- Ensure all interactive components are keyboard reachable.
- Supply alt text for images and transcripts/captions for media.
- Avoid color-only distinctions; use iconography or labels.

## Interactivity & Assessment
- Integrate 6–12 inline knowledge checks per module using registered MDX components.
- Add a checkpoint quiz (5–10 questions) with rationales mapped to exam objectives.
- Provide “If you’re stuck” guidance and escalation tips.

## Review Workflow
- Perform vibe check against this guide before submitting for review.
- Document deviations with rationale in the PR description.
