# Asking Questions: Foundation of Tanium Operations

{/* TODO: screenshot here (Console landing hero) */}

## Why Asking Questions Matters
- Every action in Tanium begins with a question. Questions help you inventory assets, confirm security posture, and decide on remediation.
- From a TCO standpoint, this domain contributes **22%** of the TAN-1000 blueprint; mastering it unlocks the later modules (Refining & Targeting, Taking Action, Reporting).
- Real environments expect you to ask the right question quickly. Practicing here saves minutes during real incidents.

## Learning Objectives (By the end you can…)
- Build and run a natural-language question from **Console → Interact** without guidance.
- Choose a matching sensor for a real-world scenario (inventory, security, operations).
- Use basic filters (contains, equals) and targeting (computer groups) to narrow scope safely.
- Save, rerun, and export a question so teammates can review results.

## Vocabulary Quick Reference
<Callout type="definition" title="Baseline Terms">
  - **Console**: The Tanium web interface. Sign in at `https://<your-tenant>.tanium.com`.<br/>
  - **Interact**: The module where you ask questions and view answers.<br/>
  - **Sensor**: A script that collects specific endpoint data (e.g., *Computer Name*).<br/>
  - **Question**: A request formed as "Get *sensor* from *targets* where *filters*".<br/>
  - **Relevance**: Tanium's engine that translates questions into endpoint instructions.<br/>
  - **Computer Groups**: Logical sets of machines (e.g., "Windows 11 laptops"). Used for targeting.<br/>
  - **Saved Question**: A named question that runs on a schedule or on demand.<br/>
  - **Package & Action**: Used to remediate; covered in "Taking Action".<br/>
</Callout>

## Step 2 – Build Your First Question
### Concept
Tanium's natural-language format is: **Get `[Sensor]` from `[Targets]` where `[Filter]`**. For beginners, keep it to one sensor and the default target `all machines`.

### Live Example (Inventory Baseline)
<Callout type="try" title="Try it now – Inventory">
  - In the Question Builder, type: `Get Computer Name from all machines`.
  - Press **Ask Question**.
  - Observe the results grid populate with endpoint names.<br/>

## Step 3 – Choose the Right Sensor
You do not need all 500+ sensors on day one. Start with the high-signal sensors below.

| Scenario | Recommended Sensor | Why it helps |
| --- | --- | --- |
| Inventory hostname | Computer Name | Baseline device identity. |
| OS rollup | Operating System | Quickly find Windows vs. macOS vs. Linux. |
| Patch check | Installed Patches | Validate hotfix status. |
| App presence | Installed Applications | Confirm software installs. |
| Logged on user | Logged In User | Identify active sessions. |
| Network reach | IP Address | Spot subnets or remote locations. |

## Step 4 – Add Filters & Basic Targeting
Filtering and targeting become deeper in Module 2, but you need a preview now.

<Callout type="caution" title="Safety first">
  Filters do not change endpoints—they only change the answer set. Actions and packages (covered later) do the remediation work.
</Callout>

**Basic Filters**
- `contains`: good for partial matches (`Computer Name contains LON-`).
- `equals`: exact match; use with caution to avoid typos.
- `and` / `or`: combine conditions, but keep it simple here.

**Targeting Basics**
- Keep default target `all machines` for visibility.
- To limit scope, select **Saved Computer Group → Windows Clients** (example) from the targeting dropdown.<br/>

## Step 5 – Saved vs. Ad-hoc Questions
**Ad-hoc** questions: typed into the builder and run once. **Saved** questions: stored with a schedule or manual replay.

<Callout type="definition" title="Saved Question">
  A named question you can rerun or schedule. It retains the sensor, filters, and target.
</Callout>

<Steps>
  <Step>After running a question, select **Save Question** above the grid.</Step>
  <Step>Name it descriptively (e.g., "Windows 11 Readiness – Weekly").</Step>
  <Step>Add a brief description (what decision it supports).</Step>
  <Step>Choose an appropriate **Folder** and optional **Computer Group**.</Step>
  <Step>Click **Save**.</Step>
</Steps>

## Step 6 – Interpret & Export Results
<Callout type="note" title="Result Grid Essentials">
  - Sort columns to find outliers (click header → Sort Asc/Desc).<br/>
  - Use **Group Results** to bucket answers (e.g., by Operating System).<br/>
  - Use **Copy** (for clipboard) or **Export → CSV** to share data.<br/>
</Callout>

<Steps>
  <Step>Run your saved question.</Step>
  <Step>Select **Export → CSV** (top right of the results grid).</Step>
  <Step>Choose delimiter (default is comma) and confirm export.</Step>
  <Step>Download the CSV and spot-check a few rows.</Step>
</Steps>

## Troubleshooting Fast Fixes
- **No results**: Confirm sensor is spelled correctly and endpoints are online. Swap `contains` for a broader filter.
- **Too many results**: Apply a computer group or add a second filter (preview in Module 2).
- **Permission errors**: Check if your role includes Interact, Saved Questions, and Export privileges.
- **Slow answers**: Start with one sensor; add others once you confirm the data set is manageable.
