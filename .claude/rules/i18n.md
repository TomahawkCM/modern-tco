# Internationalization Rules

- All user-facing strings must use `useTranslations` from `next-intl`
- Translation keys follow dot-notation: `{page}.{section}.{element}` (e.g., `budget.import.title`)
- New keys must be added to `src/i18n/messages/en.json` first, then propagated
- Never hardcode user-facing strings — even error messages
- Date/number formatting: use `useFormatter` from `next-intl`, not manual formatting
- 113 locales maintained — changes to message structure must be backward-compatible
- Pluralization: use ICU message format (`{count, plural, one {# item} other {# items}}`)
